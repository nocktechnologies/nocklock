# Runbook: release

`next` holds the integration batch; `main` holds released code. Mira gates and merges. Builders deliver one card per PR with base `next`; they do not merge or push directly to either shared branch. This repo has no publishing workflow or release script: tagging, GitHub release creation and the Homebrew tap update remain explicit release-owner actions.

## Prepare the batch

1. **Land card PRs in `next`.** Each carries its `[Unreleased]` changelog entry and relevant docs. Follow the [review pipeline](../../.claude/review/PIPELINE.md): exact-head Gander Opus and Sol review, CodeRabbit, `claude-review`, all applicable CI, and Mira's gate. Findings go into one remediation-round spec for the same builder. Mira squash-merges each accepted PR.
2. **Check the integrated batch.** `test.yml` and `network-egress.yml` run on pushes to `next` and `main`. Require successful build/vet/fmt/tests, Linux proofs, macOS DNS/network-floor proof, root netns jobs and the red-team bench. A ready PR must also have a successful native macOS SBPL/full-suite run: that job is deliberately skipped on pushes and manual dispatch. Run `go test -tags=integration ./...` on hosts with the relevant platform prerequisites; record what ran and what could not run.
3. **Prepare release notes on `next`.** Use a focused release-preparation card PR based on `next` to move the batch's `[Unreleased]` entries under `## [X.Y.Z] - YYYY-MM-DD`, add a summary and leave a fresh empty `[Unreleased]`. Include `### Breaking` and `### Security` entries and upgrade instructions where applicable. Update the roadmap to distinguish implemented behavior from design-only work. Mira gates and squash-merges this preparation PR too.

## Promote once, then distribute

1. **Open one release PR, head `next`, base `main`.** It promotes the complete reviewed batch, rather than individual feature PRs to `main`. Freeze the batch at its final head while gating it. The PR body identifies included cards/PRs, the release version, reviews, platform evidence and remaining limits.
2. **Gate the promotion head.** Obtain Gander's Opus and Sol receipts and successful CodeRabbit, `claude-review` and all applicable CI on that exact head. The current main ruleset additionally requires `Analyze (go)` and an up-to-date branch; see the [live-check snapshot](../../.claude/review/PIPELINE.md#github-rules-and-ci-coverage). If updating from main or remediation changes the head, repeat review and checks on the new head. Never satisfy the gate by treating a skipped macOS/root proof as passed.
3. **Mira squash-merges the release PR into `main`.** Verify the resulting main commit and its push CI. Record both this main SHA and the release PR's final `next` head. The release tag must point to the main squash commit, not the pre-merge `next` head.
4. **Tag and publish.** The release owner creates and pushes the immutable `vX.Y.Z` tag at the verified main commit, then creates the GitHub release with the reviewed notes. Confirm the published tag, target commit and release contents. `make build` derives its version through `git describe --tags --always --dirty` (`Makefile`), so building the tagged commit matters. Never move an existing tag or replace released bytes.
5. **Update Homebrew.** Update `nocktechnologies/homebrew-tap/Formula/nocklock.rb` to the release's source-tarball URL and verified SHA-256 through the tap's review process. Check that the formula's version agrees with the tag. Then run `brew update`, install or upgrade the formula on a clean test host, `brew test nocktechnologies/tap/nocklock`, and `nocklock version`. The formula's current test only checks the version; run the product smoke below too.
6. **Back-sync main into next with a real merge commit.** After tagging, before any new card PR lands in `next`, the release owner fetches both branches and confirms `origin/next` still equals the recorded release PR head. If new unreleased work has arrived, stop and reconcile it first; do not replace its tree with the released tree. From a clean temporary branch based on `origin/next`, merge `origin/main` with `git merge --no-ff --no-commit origin/main`. Resolve every conflict, including deletions, to main's version. Confirm the staged tree (`git write-tree`) equals `origin/main^{tree}`, then create the merge commit. Verify that `origin/main` is an ancestor of this new commit and that its tree still equals `origin/main^{tree}` before pushing it to `next`. Never squash, reset, or force-push this back-sync: main's squash commit must become an ancestor of `next` so the next release can satisfy main's strict up-to-date rule. This is the **one direct push to `next`**, performed by the release owner using the `next-batch-gate` administrator bypass; every other change reaches `next` by PR. Record the merge SHA and successful next-push CI before accepting the next batch.
7. **Record completion.** Keep the main SHA, back-sync merge SHA, tag, GitHub release URL, tap revision, brew-test result and OS smoke evidence in the release/card handoff. File the session report required by `CLAUDE.md`. A failed distribution, back-sync or smoke step leaves the release handoff incomplete.

## Product smoke and current distribution limits

Use a disposable account/project without production credentials. Follow [setup](../setup.md), then run `nocklock init`, `nocklock doctor --json`, `nocklock verify --json`, `nocklock wrap -- /bin/echo WRAP_OK`, and `nocklock verify --audit`. Inspect results and signed session levels, not just command exit codes.

- **macOS:** Homebrew installs the CLI. With the default policy, require `SEATBELT`; the self-test's Linux-only syscall probe is an explicit skip, while filesystem, network and secret probes must pass.
- **Linux:** the formula installs only the CLI. Until packaging implementation ships, use the source-install binary/library steps in [setup](../setup.md#1-install); opt-in `--net-fence=netns` also requires the installed privileged helper. Run `scripts/test-init-default-linux.sh` and the applicable root/netns CI proofs. Below Landlock ABI 9, a default `CONFINED` config reports `PARTIAL` (exit 3) for Unix sockets; accept only that named limitation with the other boundaries enforced, not an arbitrary nonzero doctor result.
- **Release assets:** the [Linux packaging design](../design/linux-packaging.md) proposes a signed tarball and clean-machine acceptance. A merged design does not supply an installer, signed assets or clean-host evidence. Publish assets only after that implementation and its acceptance gates have landed.

## Rolling back

Do not move tags. Put the correction or revert through a card PR to `next` and one gated release promotion to `main`, then issue a new patch version with the relevant `### Security` or `### Fixed` entry. Coordinate a defective tap formula with its owner and repeat the installation smoke.
